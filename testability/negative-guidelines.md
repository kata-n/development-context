# 異常系テストの観点と網羅的な洗い出し

テストケースの異常系を洗い出すためには、様々な視点と観点が必要です。ここでは、主要な考え方と具体的な例を組み合わせて、網羅的に異常系を洗い出すための方法を解説します。

## 1. 入力値の異常系

- **データ型とフォーマットの不正:**
  - 数値項目に文字を入力する
  - 日付項目に存在しない日付 (例: 2023 年 2 月 30 日) を入力する
  - 必須項目を空欄にする
  - 電話番号の桁数が不足または超過する
  - メールアドレスの形式が正しくない (例: アットマークがない)
  - ファイルアップロードで、許可されていない拡張子のファイルをアップロードする
  - 数値項目の範囲外の値を入力する (例: 年齢に負の数や極端に大きな値を入力する)
  - 文字列項目の文字数制限を超える文字列を入力する
  - 特殊文字や制御文字 (例: 改行コード、タブ) を入力する
- **境界値分析:**
  - 最小値、最大値、最小値-1、最大値+1 の値を試す
  - 配列やリストの要素数が 0、1、最大値の場合を試す
- **同値分割:**
  - 入力値を有効な範囲と無効な範囲に分割し、それぞれの代表値を試す
- **不正な組み合わせ:**
  - 複数の入力項目が関連する場合、通常ではありえない組み合わせを試す (例: 過去の日付の開始日と未来の日付の終了日)
- **文字コード:**
  - 全角文字、半角文字、特殊文字 (例: 絵文字) を試す
  - サロゲートペア文字 (Unicode の一部) を試す
  - 異なる文字コード (例: UTF-8, Shift-JIS) で入力する
- **SQL インジェクション:**
  - データベースに直接アクセスするような文字列を入力して、不正な操作を試みる (例: `'; DROP TABLE users; --`)
- **クロスサイトスクリプティング(XSS):**
  - HTML タグや JavaScript コードを入力して、Web ページに不正なスクリプトを埋め込むことを試みる (例: `<script>alert('XSS')</script>`)
- **コマンドインジェクション:**
  - OS コマンドを実行できるような文字列を入力して、不正な操作を試みる (例: `ls -al; rm -rf /`)

## 2. 処理フローの異常系

- **タイムアウト:**
  - 処理時間が異常に長くなる場合を想定する (例: ネットワークの遅延、データベースの負荷)
- **リソース不足:**
  - メモリ不足、ディスク容量不足、ファイルハンドル不足などをシミュレートする
- **競合状態 (コンカレンシー):**
  - 複数のユーザーが同時に同じリソースにアクセスする場合を想定する
  - デッドロックが発生する可能性を考慮する
- **トランザクションの失敗:**
  - データベースのトランザクションがロールバックされる場合を想定する
- **外部システム連携の失敗:**
  - 連携先のシステムがダウンしている、応答が遅い、エラーを返す場合を想定する
- **認証・認可の失敗:**
  - 不正なユーザー ID/パスワードでログインを試みる
  - 権限のない操作を実行しようとする
- **セッション管理:**
  - セッションタイムアウト、セッション ID の不正操作などを試す
- **状態遷移の異常:**
  - 想定外の順番で画面遷移や処理を実行する (例: 注文処理中に在庫管理画面に戻る)
- **割り込み:**
  - 処理中に割り込みが発生した場合の動作を確認する (例: 電話着信、タスク切り替え)
- **例外処理:**
  - 意図的に例外を発生させ、適切なエラー処理が行われるかを確認する (例: ファイルが見つからない、ネットワーク接続エラー)

## 3. 環境の異常系

- **ネットワーク:**
  - ネットワーク接続が切断される、遅延が発生する
  - DNS サーバーが利用できない
  - プロキシサーバーの設定が間違っている
- **サーバー:**
  - サーバーがダウンする、再起動する
  - サーバーの負荷が高い
  - サーバーの時刻がずれている
- **データベース:**
  - データベースサーバーがダウンする、再起動する
  - データベースの接続数が上限に達する
  - データベースのデータが破損する
- **OS:**
  - OS がクラッシュする、再起動する
  - OS のバージョンが異なる
- **ブラウザ:**
  - サポートされていないブラウザを使用する
  - ブラウザのキャッシュが古い
  - ブラウザの設定が異なる (例: Cookie が無効になっている)
- **デバイス:**
  - メモリ不足、ストレージ不足
  - バッテリー残量が少ない
  - デバイスの時刻がずれている
- **仮想環境:**
  - 仮想マシンのリソース割り当てが不足する
  - 仮想ネットワークの設定が間違っている

## 4. その他の観点

- **セキュリティ:**
  - 個人情報や機密情報の漏洩を防ぐ
  - 不正アクセスを防止する
  - 脆弱性を悪用されないようにする
- **パフォーマンス:**
  - レスポンス時間が遅延する場合を想定する
  - 高負荷時の動作を確認する
- **ユーザビリティ:**
  - エラーメッセージがわかりやすいか
  - 操作手順が複雑すぎないか
- **国際化・ローカライゼーション:**
  - 異なる言語や地域に対応できているか
  - 日付、時刻、通貨などの表示が正しいか
- **アクセシビリティ:**
  - 障碍を持つユーザーでも利用できるか

## 異常系洗い出しの具体的な進め方

1.  **仕様書・設計書のレビュー:**
    - 仕様書や設計書を詳細に読み込み、潜在的なリスクやエラーが発生しやすい箇所を特定します。
    - 曖昧な記述や矛盾点がないかを確認します。
2.  **リスク分析:**
    - システム全体のリスクを洗い出し、それぞれの発生確率と影響度を評価します。
    - リスクの高い箇所から重点的にテストケースを作成します。
3.  **ブレインストーミング:**
    - テストチームでブレインストーミングを行い、様々な異常系のアイデアを出し合います。
    - 経験豊富なメンバーの知識や経験を活用します。
4.  **チェックリストの活用:**
    - 過去のプロジェクトで発生した不具合や、一般的な異常系のチェックリストを参考にします。
    - 業界標準のセキュリティチェックリスト (OWASP など) も活用します。
5.  **テスト技法の適用:**
    - 境界値分析、同値分割、デシジョンテーブルテスト、状態遷移テストなどのテスト技法を適用し、網羅的にテストケースを作成します。
6.  **探索的テスト:**
    - テストケースに基づかない自由なテストを実施し、予期せぬ不具合を発見します。
    - 経験豊富なテスターが、システムの挙動を深く理解しながらテストを行います。
7.  **テスト結果の分析:**
    - テスト結果を分析し、不具合の傾向やパターンを把握します。
    - 見つかった不具合を修正し、再テストを実施します。
8.  **レビューと改善:**
    - テストケースやテストプロセスを定期的にレビューし、改善点を見つけます。
    - 過去の不具合事例を分析し、今後のテストに活かします。

## 効果的な異常系テストのポイント

- **早期段階でのテスト実施:** 開発の早い段階からテストを実施することで、手戻りを減らすことができます。
- **自動テストの活用:** 反復的なテストや負荷テストは自動化することで、効率的にテストを実施できます。
- **十分なテスト環境の準備:** 本番環境に近いテスト環境を用意することで、より現実的なテストを実施できます。
- **関係者との連携:** 開発者、インフラ担当者、運用担当者など、関係者と密に連携することで、より質の高いテストを実施できます。
